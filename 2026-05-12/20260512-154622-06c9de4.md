## AI 评审结果

总体评价  
本次改动将若干硬编码逻辑拆分为独立 Service/Config 类，并补充了日志 / 微信通知等功能，整体可读性与扩展性有所提升。但 CI 流程 YAML 存在严重缩进问题，可能导致评审步骤根本不被执行；同时仍有少量安全、健壮性细节需完善。

=============

1. .github/workflows/main-maven-jar.yml  
   🔴严重  Step“Run Code Review” 的 run 字段被错误地放进 env 块  
   • YAML 中 `env:` 下的所有同层字段都会被视为环境变量键值对，目前 diff 后效果为：  
     ```
     env:
       OPENAI_API_KEY: ...
       ...
       run: java -jar ...
     ```  
     这会把 `run` 当作环境变量而不是 step 命令，导致评审 jar 实际上不会执行。请将 `run:` 与 `env:` 保持同一缩进层级。  

   🟡建议  PAT 直接出现在 `git clone` URL 中可能泄漏  
   • Actions log 默认不会打印 URL，但若以后有人在脚本中输出 remote 信息，token 就会暴露。  
   • 建议改为：  
     ```
     git clone https://github.com/Laqcce-cao/Laqcce-cao-openai-code-review-log.git
     git remote set-url origin https://${LOG_REPO_TOKEN}@github.com/Laqcce-cao/...
     ```  
     或使用 `GITHUB_TOKEN`+`actions/checkout`。  

   🟡建议  未对空日志进行保护  
   • `cp review-output.md ...` 若文件不存在，脚本直接失败。可在复制前加 `[ -f review-output.md ] || exit 0`。  

   🟢优化  Git 提交前判断是否有变更的写法简洁，值得肯定。  

2. openai-code-review-sdk/src/main/java/cn/laqcce/ai/sdk/OpenAiCodeReview.java  
   🔴严重  `pushWechatNotification(diffContent, reviewResult);` 传入未经截断的 diff  
   • 微信模板消息正文长度限制较小，超长将导致发送失败并抛异常。  
   • 建议与调用 AI 一样使用 `truncatedDiff`，或在 WeChatService 内部再做长度校验。  

   🟡建议  saveReviewLog 使用 `new FileWriter(LOG_FILE)` 依赖平台默认编码  
   • 在 GitHub Runner 上虽默认为 UTF-8，但本地执行可能出现乱码，建议改为  
     `new OutputStreamWriter(new FileOutputStream(LOG_FILE), StandardCharsets.UTF_8)`  
     或 `Files.newBufferedWriter(.., StandardCharsets.UTF_8)`。  

   🟡建议  LOG_FILE 常量名较好，但固定文件名可能在并发执行时互相覆盖  
   • 若未来支持并行 job，可考虑在文件名中加入时间戳或由外部传入。  

   🟢优化  将原先冗长的 HTTP/JSON 处理拆分到 `OpenAiClient`，代码简洁度提升明显。  

   🟢优化  新增 `ReviewConfig.getMaxDiffChars()` 统一读取配置，符合单一职责原则。  

=============  
总结  
请优先修复 YAML 缩进错误；同时留意长文本在微信通知中的截断、安全地使用 PAT 以及输出文件编码问题。其余重构方向正确，可继续保持。
